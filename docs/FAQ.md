# 常见问题

按「被问到的频率」排序。前三个覆盖了绝大多数情况。

诊断神器：**点浏览器工具栏里的扩展图标**（🧩 → HTML Studio），会打开自检页，
实时检查「扩展已加载 / 文件访问权限 / 本地程序连通性」，哪项红了直接告诉你怎么修。

命令行等价：

```bash
cd <你的目录>/extension && python3 install.py --check
```

## 1. 本地 html 页面右下角没有 ✎ 按钮

**99% 是没开「允许访问文件网址」。**

打开方法：`chrome://extensions` → 找到 HTML Studio → 点「**详情**」→ 打开「**允许访问文件网址**」。
然后**刷新那个本地页面**（开关对已打开的页面不生效）。

这个开关默认是关的，而且不开的话**没有任何报错**，浏览器只是安静地不给扩展注入权限。

顺带确认两件事：

- 地址栏必须是 `file:///...` 开头才是「自动出 ✎」的场景。**网页（`http/https`）默认不挂 ✎**，
  要在网页上编辑，点工具栏图标 / `Cmd+Shift+E` / 右键「HTML Studio：编辑本页」
  （详见 [第 13 条](#13-别人发给我一个-html-网页我能直接改吗)）。
- 装完扩展或改完开关后，**完全退出浏览器再重开**（native host 注册只在启动时读取）。

## 2. 点保存报「无法连接本地 host」/「Specified native messaging host not found」

本地程序没注册上，或者注册了但浏览器还没重新读。

```bash
cd <你的目录>/extension
python3 install.py          # 重新注册
```

然后 **`Cmd+Q` 完全退出浏览器再打开**（关窗口不算 —— Chrome 开了「关闭后继续运行后台应用」时进程还在）。

再用 `python3 install.py --check` 确认「活体 ping」那一行是 ✅。

> 如果你是**从 Chrome 应用商店**装的扩展，扩展 ID 和源码里的不一样，需要显式指定：
> `python3 install.py --ext-id <商店页面显示的ID>`

## 3. 加载扩展时报「清单文件缺失或不可读取」

Chrome 这句报错很含糊，实际有两个完全不同的原因：

**a) 选错了文件夹。** 要选 `extension/` 这一层（里面有 `manifest.json`），不是外层仓库目录。

**b) `extension/` 里有以 `_` 或 `.` 开头的文件/目录。** Chrome 把这类名字视为系统保留，
只要存在一个，整个扩展就加载失败 —— 而报错信息完全不会提到它。

最常见的是 `__pycache__`（在 extension 目录里跑 `py_compile` 或 `import native_host` 就会生成）。

```bash
ls -A extension | grep -E '^[_.]'     # 有输出就说明中招了
rm -rf extension/__pycache__          # 删掉即可，无任何损失
python3 install.py --check            # 现在会自动清理这一项
```

## 4. 保存了，但文件的缩进 / 换行变了

这是**已知边界，不是 bug**。保存是把浏览器里当前的 DOM 序列化写回文件：

- 文本、结构、class、属性都保留
- `<svg>` 里的自闭合标签（`<line/>`）做了还原处理
- 但浏览器会重新规范化一次缩进和换行

实测：一个 118 行的 AI 生成页面只改一个词，落盘差 10 行（**1 行真实改动 + 3 行空白归一化**）。
对 AI 生成的 HTML 通常无所谓；如果你要拿它做 git 版本管理，第一次保存的 diff 会比较吵。

## 5. 页面里有些内容保存后「变多了」/ 重复了

如果那个页面用 `<script>` 在加载后动态生成 DOM，那部分**动态生成的内容也会被写进文件**。
下次打开时脚本再跑一遍，就可能看起来重复。

处理办法：改完看底部 diff（网页版会直接显示），不对就点「**撤销保存**」—— 有备份兜底，原文件不会丢。

## 6. 改坏了 / 想退回去，怎么恢复

先分清楚是哪种情况，三种情况用的东西完全不同：

| 情况 | 用什么 | 依赖本地程序吗 |
| --- | --- | --- |
| **改到一半，还没保存**（或保存失败了） | `Cmd/Ctrl+Z` 撤销输入；或工具条「**⋯**」→「放弃改动」（丢弃全部改动、从文件重新加载） | ❌ 不需要 |
| **已经保存了，想回到保存前** | 工具条「**⋯**」→「撤销上一次保存」 | ✅ 需要 |
| **想回到更早的某一版** | 工具条「**⋯**」→「备份历史 / 恢复」→ 选一版「恢复」 | ✅ 需要 |

> 如果保存报错（本地程序连不上），那么「撤销保存」和「备份」也会一起失效 ——
> 它们都要经过本地程序才能操作备份文件。这种情况下想丢掉改动，用「**放弃改动**」或 `Cmd+Z`，
> 这两个不依赖本地程序，直接作用于当前页面。

每次保存前都会自动备份，**任意历史版本都能拿回来**。备份位置：

```
~/.html-studio/backups/<相对路径>.bak/     # 扩展版
<工作目录>/.edits/backups/                # 网页版
```

网页版用顶部「撤销保存」/「备份」。恢复本身也会先备份一次，所以恢复也能撤回。

## 7. 为什么要装一个本地程序？安全吗

浏览器的安全模型不允许扩展直接写磁盘 —— 这是故意的设计，否则任何扩展都能改你的文件。
所以扩展保存文件必须有本地程序配合（这叫 native messaging，是 Chrome 官方机制）。

这个本地程序做了什么、不做什么：

- 只接受 `$HOME` 内、以 `.html/.htm/.xhtml` 结尾、路径中不含隐藏目录的文件
- 拒绝保存空内容（防止把源文件清成空）
- 每次写入前备份，可回滚
- **不联网、不收集数据、没有远程代码**，全部本地执行，源码就是 `extension/native_host.py`（约 300 行，纯标准库）

## 8. Windows / Linux 能用吗

| | macOS | Linux | Windows |
| --- | --- | --- | --- |
| 扩展 + 本地程序 | ✅ | ✅ 逻辑相同，未实机验证 | ⚠️ 实验性，未实测 |
| 本地网页版 | ✅ | ✅ | ✅ |

Windows 需要注册表登记 + `.cmd` 启动器，代码写了但作者没有 Windows 机器验证过。
如果你在 Windows 上跑通了（或踩到坑），非常欢迎在 issue 里反馈。

Linux 上如果 `install.py` 没找到你的浏览器，可以手动把 host manifest 放到
`~/.config/<你的浏览器>/NativeMessagingHosts/`。

## 9. 怎么彻底卸载

```bash
cd <你的目录>/extension
python3 install.py --uninstall      # 移除本地程序注册
```

然后 `chrome://extensions` 里移除扩展。最后想清干净可以删掉备份：

```bash
rm -rf ~/.html-studio               # 扩展版的备份和日志
```

你的 html 文件不会被删，撤销过的东西也都在 `~/.html-studio/backups/` 里。

## 10. 点了工具栏图标没反应

- 在**任何 html 页面**上（本地文件或网页）：图标是用来开关编辑模式的 —— 页面右下角会出现工具条
- 在**非 html 页面**上（新标签页、PDF、`chrome://` 页面）：会打开自检页。这是预期行为，因为那些页面注入不了内容脚本
- 想随时打开自检页：右键扩展图标 →「HTML Studio：自检 / 帮助」

扩展没有弹窗面板（那种点图标弹小窗的）—— 因为编辑必须在页面本身上做，弹窗里改不了你的网页。

快捷键 `Cmd/Ctrl+Shift+E` 等价于点图标。可以在 `chrome://extensions/shortcuts` 里改。

## 11. 为什么不做 XXX —— 这个项目的边界

这个工具的定位很窄：**AI 已经帮你把页面生成好了，你只是想改里面那几个字。**
守住这个定位是它好用的原因 —— 一旦开始加功能，就会变成又一个半吊子富文本编辑器。

下面这些**是刻意不做的**，不是没想到：

| 你可能想要 | 为什么这里不做 | 更适合用什么 |
| --- | --- | --- |
| 完整的富文本编辑器（颜色、行距、表格、页边距、插入形状） | 样式面板做得越全，越要跟页面自己的 CSS 打架（AI 生成页面通常自带设计系统），最后两边规则互相覆盖，越改越乱。目前只做了**最常被要求的两项**：字体和字号 | 改提示词让 AI 重新生成；或 VS Code + Live Preview |
| 直接编辑 HTML 源码 | 那是另一类工具，而且已经做得极好；本项目的价值恰恰是**让你不用看标签** | VS Code / Sublime Text / Zed |
| 编辑 Markdown / Vue / JSX / Astro | 保存靠 DOM 序列化，这条路只对 HTML 安全。对 Markdown 这类格式，序列化会把源码结构破坏掉 | Typora / Obsidian / VS Code |
| 正则批量替换、跨文件替换 | 危险，且用脚本更合适；在编辑器里做容易误伤一批文件 | `sed` / `ripgrep` / 写个 Python 脚本 |
| 内置图片裁剪、压缩 | 属于图像处理，跟"改文字"是两件事；且好的图像工具已经太多 | 系统预览 / Squoosh / ImageOptim |
| 云同步、多端、协作 | 定位是 local-first：你的文件不进任何服务器（这也是它的安全承诺） | Git / iCloud / Syncthing |
| 自动保存（不用按 `Cmd+S`） | 每次保存都会重排一次空白并生成一份备份。自动保存会让 diff 和备份变成噪音，也失去了"我确认过了"这个明确边界 | — |
| 撤回已保存的修改（`Cmd+Z` 跨会话） | 「撤销保存」+ 备份面板已覆盖，而且能回溯到任意历史版本，比单步撤销更实用 | — |

### 核心取舍：为什么保存是「整体序列化」而不是「精准替换那一段」

这是最容易被质疑的设计，讲清楚：

- **精准替换的方案**是：记住你改了哪个文本节点 → 在源码里定位到对应位置 → 只替换那一段。理论上 diff 最干净。
- **但它要求把 DOM 节点稳定映射回源码偏移**，需要自带一套 HTML 解析器加位置信息。遇到 `<script>` 动态生成内容、模板语法、重复文本时并不可靠 —— 一旦映射错位，就是**在你的源码里改错地方**，这比空白重排严重得多。
- **现在用的是整体序列化**：输出一定是浏览器认为合法的 HTML，不会破坏结构；代价是缩进和换行被规范化一次。

结论：**宁可 diff 大几行，也不要改错位置。** 具体影响见 [第 4 条](#4-保存了但文件的缩进--换行变了)。

### 什么样的反馈最有用

不是"能不能加个 XX 编辑器"，而是：

1. **你遇到的麻烦**（"我一次要改 10 个页面的标题，现在只能一个个点开"）—— 方案我来想
2. **能复现的最小页面**（几行 HTML 就够，别贴你完整的报告）
3. **保存前后的 diff**（网页版底部面板直接能看）

## 12. 编辑时点页面上的按钮/链接没反应？或者点保存页面跳走了？

两种情况都是「编辑模式」的预期行为。

编辑模式下，扩展会**屏蔽页面自己对点击的响应**，原因很实际：很多 AI 生成的页面是
「点一下翻下一页」的结构（`document` 上挂着 click 监听），不屏蔽的话，你点工具条上的
**保存**，页面会把它当成翻页指令 —— 变成"一保存就跳到下一页"。

具体规则：

| | 编辑模式 | 预览模式（`Cmd/Ctrl+E`） |
| --- | --- | --- |
| 点文字改内容 | ✅ | — |
| 页面自己的按钮 / 翻页 / 链接 | ❌ 不响应 | ✅ 正常 |
| 选中文字、定位光标 | ✅ 正常 | ✅ |

所以要看页面上的交互效果、点链接、翻页，**按 `Cmd/Ctrl+E` 切到预览模式**，在那里页面是真实运行的。
改完内容切回编辑模式继续改就行，内容不会丢。

> 只屏蔽点击，不阻止原生编辑行为 —— 光标定位和选中文字照常可用。

## 13. 别人发给我一个 html 网页，我能直接改吗

能，而且不需要原文件。分两步：

1. 打开那个链接（`http://` / `https://` 都行）
2. 点**工具栏的扩展图标**，或按 `Cmd/Ctrl+Shift+E`，或右键 →「HTML Studio：编辑本页」

进入编辑后就像本地文件一样改。第一次按 `Cmd+S` 时：

- 自动存成 `~/Downloads/<域名>-<路径>.html`（例如 `~/Downloads/example.com-report.html`），
  提示条里会显示完整路径
- 这只是**下载到你电脑上的一个普通 html 文件**，原网页不受任何影响
- 之后在同一个链接上再按 `Cmd+S`，写的就是这个文件（下次打开同一个链接也认得它）

想把改动存到别处：工具条「⋯」→「另存为…」，填一个绝对路径（`~` 代表主目录）。

**几个要注意的地方**：

- 存到本地时，相对路径资源（`./style.css`、`/img/a.png`、CSS 里的 `url(...)`、`srcset`）
  会自动转成**绝对地址**，所以离线打开样式和图片还在 —— 但反过来，**断网后那些外链资源就加载不出来了**
- `blob:` 开头的图片（页面用 JS 现生成的）存不下来，需要先在页面上另存图片
- 跨域 `<iframe>` 里的内容拿不到，也不会被保存
- 如果那个网页是 React / Vue 这类会自我刷新的应用，你的改动可能被它重新渲染覆盖 ——
  这种情况先存成本地文件再改

## 14. 字体 / 字号改了没生效，或者改到了整段

点 `Aa` 打开面板后：

- **选中一段文字**再改 → 只改选中的部分
- **只把光标放在一段文字里**（没有选中）→ 改的是**整段**（面板底部会写明）
- 面板里「当前」那一行显示的是光标处实际生效的字体和字号，可以拿它确认有没有改到

字体和字号写进的是**内联样式**（`<span style="font-family:…;font-size:32px">`），
优先级高于页面自己的 CSS，所以保存后打开也是你选的那一款。

如果文档整体是横向海报（比如宽度固定 1280px 的页面），改大字号后文字可能溢出容器 ——
这种情况字号给保守一点，或者同时把容器宽度调大（那是页面自己的 CSS，需要改源码）。

## 15. 拖动模块：能拖什么，拖不动怎么办

点工具条「移动」（或 `Cmd+M`）进入移动模式，此时文字编辑暂停，鼠标指向的块会显示虚线框：

- 可拖：标题、段落、图片、卡片、列表项、整段 `section`……任何「块级」元素
- **蓝色横线 / 竖线** = 会插到哪儿；松手即移动，移动模式下 `Cmd+Z` 可撤销上一步移动
- 想拖外层大容器（比如整张卡片而不是卡片里的标题）→ **按住 Shift** 再拖
- `Esc` 或再点一次「移动」退出

拖不动的常见原因：

- 目标是 `position: fixed` 的元素（导航条、悬浮按钮），这类不允许拖，避免把固定定位元素挪成流元素
- 元素太小（宽高小于 12px）会被当成装饰忽略
- 只想**同级重排**：拖到目标元素的上下/左右之间。把模块挪进另一个容器，就拖到那个容器里的元素之间

## 16. 「页面」面板说没检测到分页，或者删错了

删页需要先认出「一页」是什么。识别顺序：

1. 已知结构：`.slide` / `.page` / `.screen` / `.swiper-slide` / `[data-page]` / `.slides > section` 等
2. 结构启发式：同一父元素下有多个「高度 ≥ 视口一半」的块
3. 兜底：`body` 下多个接近满屏的块

显示「没检测到分页结构」说明这个页面是普通单页文档 —— 那就没有「页」可删，直接改内容即可。

删页的注意事项：

- 删掉的只是那个 DOM 块；**页面里靠 JS 数组控制翻页的 deck，删完翻页逻辑可能需要你再看一眼**
- 没保存前想反悔：直接刷新页面即可（或「⋯」→「放弃改动」）
- 已保存想反悔：「⋯」→「备份历史」选上一版恢复

如果你的多页 HTML 用的是别的类名（比如 `.my-card-page`），告诉我，加一条识别规则就行。
