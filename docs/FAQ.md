# 常见问题

按「被问到的频率」排序。前三个覆盖了绝大多数情况。

诊断神器：**点浏览器工具栏里的扩展图标**（🧩 → HTML Studio），会打开自检页，
实时检查「扩展已加载 / 文件访问权限 / 本地程序连通性」，哪项红了直接告诉你怎么修。

命令行等价：

```bash
cd <你的目录>/extension && python3 install.py --check
```

---

## 1. 本地 html 页面右下角没有 ✎ 按钮

**99% 是没开「允许访问文件网址」。**

打开方法：`chrome://extensions` → 找到 HTML Studio → 点「**详情**」→ 打开「**允许访问文件网址**」。
然后**刷新那个本地页面**（开关对已打开的页面不生效）。

这个开关默认是关的，而且不开的话**没有任何报错**，浏览器只是安静地不给扩展注入权限。

顺带确认两件事：

- 地址栏必须是 `file:///...` 开头。如果你是通过 `http://127.0.0.1:7788` 看文件，那是**网页版的界面**，
  走的是另一条路（那个页面自己就是编辑器），扩展不会介入。
- 装完扩展或改完开关后，**完全退出浏览器再重开**（native host 注册只在启动时读取）。

## 2. 点保存报「无法连接本地 host」/「Specified native messaging host not found」

本地程序没注册上，或者注册了但浏览器还没重新读。

```bash
cd <你的目录>/extension
python3 install.py          # 重新注册
```

然后 **`Cmd+Q` 完全退出浏览器再打开**（关窗口不算 —— Chrome 开了「关闭后继续运行后台应用」时进程还在）。

再用 `python3 install.py --check` 确认「活体 ping」那一行是 ✅。

> 如果你是**从 Chrome 应用商店**装的扩展，扩展 ID 和源码里的不一样，需要显式指定：
> `python3 install.py --ext-id <商店页面显示的ID>`

## 3. 加载扩展时报「清单文件缺失或不可读取」

Chrome 这句报错很含糊，实际有两个完全不同的原因：

**a) 选错了文件夹。** 要选 `extension/` 这一层（里面有 `manifest.json`），不是外层仓库目录。

**b) `extension/` 里有以 `_` 或 `.` 开头的文件/目录。** Chrome 把这类名字视为系统保留，
只要存在一个，整个扩展就加载失败 —— 而报错信息完全不会提到它。

最常见的是 `__pycache__`（在 extension 目录里跑 `py_compile` 或 `import native_host` 就会生成）。

```bash
ls -A extension | grep -E '^[_.]'     # 有输出就说明中招了
rm -rf extension/__pycache__          # 删掉即可，无任何损失
python3 install.py --check            # 现在会自动清理这一项
```

## 4. 保存了，但文件的缩进 / 换行变了

这是**已知边界，不是 bug**。保存是把浏览器里当前的 DOM 序列化写回文件：

- 文本、结构、class、属性都保留
- `<svg>` 里的自闭合标签（`<line/>`）做了还原处理
- 但浏览器会重新规范化一次缩进和换行

实测：一个 118 行的 AI 生成页面只改一个词，落盘差 10 行（**1 行真实改动 + 3 行空白归一化**）。
对 AI 生成的 HTML 通常无所谓；如果你要拿它做 git 版本管理，第一次保存的 diff 会比较吵。

## 5. 页面里有些内容保存后「变多了」/ 重复了

如果那个页面用 `<script>` 在加载后动态生成 DOM，那部分**动态生成的内容也会被写进文件**。
下次打开时脚本再跑一遍，就可能看起来重复。

处理办法：改完看底部 diff（网页版会直接显示），不对就点「**撤销保存**」—— 有备份兜底，原文件不会丢。

## 6. 改坏了怎么恢复

每次保存前都会自动备份，**任意历史版本都能拿回来**：

- **扩展版**：工具条「备份」→ 选一版「恢复」；或「撤销保存」直接回到上一次保存前
- **网页版**：顶部「撤销保存」，或「备份」→ 对比 / 恢复

备份位置：

```
~/.html-studio/backups/<相对路径>.bak/     # 扩展版
<工作目录>/.edits/backups/                # 网页版
```

恢复本身也会先备份一次，所以恢复也能撤回。

## 7. 为什么要装一个本地程序？安全吗

浏览器的安全模型不允许扩展直接写磁盘 —— 这是故意的设计，否则任何扩展都能改你的文件。
所以扩展保存文件必须有本地程序配合（这叫 native messaging，是 Chrome 官方机制）。

这个本地程序做了什么、不做什么：

- 只接受 `$HOME` 内、以 `.html/.htm/.xhtml` 结尾、路径中不含隐藏目录的文件
- 拒绝保存空内容（防止把源文件清成空）
- 每次写入前备份，可回滚
- **不联网、不收集数据、没有远程代码**，全部本地执行，源码就是 `extension/native_host.py`（约 300 行，纯标准库）

## 8. Windows / Linux 能用吗

| | macOS | Linux | Windows |
| --- | --- | --- | --- |
| 扩展 + 本地程序 | ✅ | ✅ 逻辑相同，未实机验证 | ⚠️ 实验性，未实测 |
| 本地网页版 | ✅ | ✅ | ✅ |

Windows 需要注册表登记 + `.cmd` 启动器，代码写了但作者没有 Windows 机器验证过。
如果你在 Windows 上跑通了（或踩到坑），非常欢迎在 issue 里反馈。

Linux 上如果 `install.py` 没找到你的浏览器，可以手动把 host manifest 放到
`~/.config/<你的浏览器>/NativeMessagingHosts/`。

## 9. 怎么彻底卸载

```bash
cd <你的目录>/extension
python3 install.py --uninstall      # 移除本地程序注册
```

然后 `chrome://extensions` 里移除扩展。最后想清干净可以删掉备份：

```bash
rm -rf ~/.html-studio               # 扩展版的备份和日志
```

你的 html 文件不会被删，撤销过的东西也都在 `~/.html-studio/backups/` 里。

## 10. 点了工具栏图标没反应

- 如果你在**本地 html 页面**上：图标是用来开关编辑模式的，效果是页面右下角的 ✎ / 工具条切换
- 如果在**其它页面**（新标签页、普通网站）：会打开自检页 —— 这是预期行为，用来告诉你哪一步没配好

扩展没有弹窗面板（那种点图标弹小窗的）—— 因为编辑必须在页面本身上做，弹窗里改不了你的网页。
